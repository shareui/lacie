## 1. Обзор и концепция

Lacie устанавливает готовые исполняемые файлы без необходимости прав суперпользователя (`root` / администратор).

Ключевые принципы:
- **Модель нулевого доверия:** релизы обязаны предоставлять контрольные суммы. Непроверенные манифесты и скрипты жизненного цикла требуют подтверждения перед запуском.
- **Сосуществование версий:** разные версии одного пакета хранятся параллельно в каталоге `bin/{id}/{version}/`. В `PATH` активна только одна версия, но переключение между ними происходит мгновенно.
- **Безопасные обновления:** при обновлении новая версия скачивается рядом со старой. Если обновление работает нестабильно, можно сразу вернуть предыдущую версию.
- **Управление ссылками:** в Unix-системах Lacie создает символические ссылки в `active/`. В Windows 11 активный бинарник копируется в `active/`.

## 2. Установка и первый запуск

### Начальная настройка (`init-lacie`)

Инициализируйте рабочее окружение командой:

```bash
lacie init-lacie
```

Интерактивный мастер задаст 5 основных вопросов:
1. **Language:** язык интерфейса — русский (`ru`), английский (`en`) или автоопределение (`auto`).
2. **Colors:** цветовая схема терминала (`terminal`), 256 цветов (`always`) или отключено (`never`).
3. **Verify SHA256:** строгая проверка контрольных сумм скачиваемых файлов (`true`/`false`).
4. **Auto Switch:** автоматическая активация только что установленной версии (`true`/`false`).
5. **Confirm:** запрос подтверждения перед установкой, обновлением или удалением (`true`/`false`).

### Настройка переменной PATH

Lacie размещает исполняемые файлы в каталоге `active/`:
- **Unix:** `~/lacie/active`
- **Windows:** `%LOCALAPPDATA%\lacie\active`

Добавьте этот путь в переменную окружения `PATH`:

#### Bash / Zsh (`~/.bashrc` или `~/.zshrc`):
```bash
export PATH="$HOME/lacie/active:$PATH"
```

#### Fish (`~/.config/fish/config.fish`):
```fish
fish_add_path ~/lacie/active
```

#### Windows (PowerShell):
```powershell
[Environment]::SetEnvironmentVariable("Path", $env:Path + ";$env:LOCALAPPDATA\lacie\active", "User")
```

## 3. Форматы ссылок на пакеты

Lacie распознает следующие форматы целевых пакетов:

| Формат | Назначение | Пример |
|---|---|---|
| `owner/repo` | Репозиторий через `default_source` (по умолчанию: `github`) | `lacie add shareui/nyano` |
| `source:owner/repo` | Явное указание плагина источника | `lacie add github:shareui/nyano` |
| `source:owner/repo#pkg` | Конкретный пакет из мультипакетного репозитория | `lacie add github:shareui/lacie#tool` |
| `source:owner/repo 1.2.0` | Конкретная версия или тег релиза | `lacie add github:shareui/nyano 1.0.0` |
| `https://.../archive.tar.gz` | Прямая ссылка на архив через HTTP/HTTPS | `lacie add https://example.com/bin.tar.gz` |
| `/path/to/archive.tar.gz` | Локальный файл архива (`.tar.gz`, `.tar.xz`, `.tar.zst`, `.zip`) | `lacie add ./pkg-v1.tar.gz` |
| `/path/to/lacie.toml` | Локальный файл манифеста | `lacie add ./lacie.toml` |

## 4. Справочник команд

### `add`

Устанавливает пакет в систему.

```bash
lacie add <ссылка-на-пакет> [опции]
```

**Опции:**
- `-y`, `--yes`: пропустить подтверждение и выполнить установку автоматически.
- `--show`: открыть интерактивный терминальный просмотрщик манифеста и скриптов перед установкой.
- `--list`: показать доступные релизы репозитория без скачивания и установки.
- `--info`: просмотреть метаданные пакета из манифеста без установки.
- `--force`: принудительно переустановить пакет, даже если такая версия уже присутствует.
- `--set-hash <sha256>`: явно задать ожидаемый SHA256-хэш, если в манифесте он отсутствует.
- `--ignore-hash`: пропустить проверку контрольной суммы SHA256 (не рекомендуется).
- `--max <n>`: ограничить количество выводимых результатов поиска.

**Управление в интерактивном просмотрщике (`--show`):**
- `n`: следующий файл.
- `p`: предыдущий файл.
- `a`: подтвердить установку и продолжить.
- `d` / `q`: отклонить и отменить установку.

---

### `update`

Проверяет наличие обновлений и обновляет установленные пакеты.

```bash
lacie update [пакеты...] [опции]
```

Если пакеты не указаны, проверяются все установленные программы.

**Опции:**
- `-a`, `--all`: явно проверить и обновить все установленные пакеты.
- `-y`, `--yes`: применить обновления без интерактивного подтверждения.
- `-d`, `--dry-run`: проверить обновления и вывести список доступных версий без скачивания.
- `-i`, `--ignore <пакет>`: исключить указанный пакет из процесса обновления.

---

### `switch`

Переключает активную версию уже установленного пакета без повторного скачивания.

```bash
lacie switch <пакет> <версия>
```

Пример:
```bash
lacie switch ripgrep 13.0.0
```

---

### `remove`

Удаляет пакеты или очищает неактивные версии.

```bash
lacie remove <пакеты...> [опции]
```

**Опции:**
- `-y`, `--yes`: удалить без интерактивного подтверждения.
- `--unused`: удалить только неактивные кэшированные версии, сохранив текущую активную.
- `--symlink-only`: убрать исполняемый файл из `active/` (PATH), но оставить бинарники на диске.
- `--active-only`: удалить только активную версию.
- `--no-scripts`: не выполнять хуки `preremove.rb` и `postremove.rb`.

---

### `freeze` / `unfreeze` / `frozen`

Замораживает пакет на текущей версии, предотвращая его обновление через `lacie update`.

```bash
# Заморозить пакет на текущей версии
lacie freeze <пакет>
lacie freeze ALL

# Разморозить пакет для включения обновлений
lacie unfreeze <пакет>
lacie unfreeze ALL

# Список всех замороженных пакетов
lacie frozen
```

---

### `rename`

Изменяет имя исполняемой команды в каталоге `active/` (в PATH).

```bash
# Переименовать активную исполняемую команду
lacie rename <пакет> <новое-имя-команды>

# Сбросить имя команды обратно к имени пакета с помощью константы DEFAULT
lacie rename <пакет> DEFAULT
```

Пример:
```bash
lacie rename neovim nvim
lacie rename neovim DEFAULT
```

---

### `source`

Управление источниками пакетов и плагинами реестров.

```bash
# Список всех зарегистрированных источников
lacie source list

# Добавить новый плагин источника
lacie source add <имя> <ссылка>

# Удалить сторонний плагин источника
lacie source remove <имя>

# Обновить плагины источников
lacie source update [имя]
```

---

### `list`

Выводит список установленных пакетов, их активные версии и статус заморозки.

```bash
lacie list [фильтры...] [опции]
```

**Опции:**
- `--json`: вывод данных в формате JSON-массива.
- `[фильтры]`: критерии выборки (см. [Синтаксис фильтров](#5-синтаксис-фильтров)).

---

### `info`

Показывает подробные сведения и историю версий установленного пакета.

```bash
lacie info <пакет>
```

Отображает: ID пакета, активную версию, список всех установленных версий, размер на диске, имя исполняемого файла, автора, ссылки и дату установки.

---

### `doctor`

Проверяет целостность окружения Lacie и сообщает о найденных проблемах.

```bash
# Диагностика состояния окружения
lacie doctor

# Автоматическое устранение найденных проблем структуры, файлов плагинов и PATH
lacie doctor --fix
```

Проверяет:
- Наличие и права доступа к домашнему каталогу Lacie.
- Интеграцию пути `active/` в переменную `PATH`.
- Корректность симлинков и исполняемых файлов.
- Целостность файлов баз данных (`packages.toml`, `sources.toml`, `seen.toml`, `scripts.toml`).
- Работоспособность установленных плагинов источников.

---

### `config`

Просмотр и изменение параметров конфигурации.

```bash
# Вывести все параметры, их текущие значения и значения по умолчанию
lacie config list

# Получить текущее значение ключа
lacie config get <ключ>

# Установить новое значение
lacie config set <ключ> <значение>

# Сбросить значение параметра к значению по умолчанию константой DEFAULT
lacie config set <ключ> DEFAULT
```

Пример:
```bash
lacie config set language ru
lacie config set confirm false
lacie config set colors DEFAULT
```

---

### `export` и `import`

Экспорт и импорт состава установленных пакетов.

```bash
# Экспорт текущего состояния в файл (по умолчанию: lacie-lock.toml)
lacie export [файл] [опции]

# Экспорт в стандартный вывод (stdout)
lacie export -

# Восстановление состояния из файла
lacie import [файл]

# Восстановление состояния из stdin
lacie import -
```

**Опции экспорта:**
- `--all-versions`: экспортировать все скачанные версии, а не только активные.
- `--with-config`: включить в файл экспорта пользовательские настройки `config.toml`.

---

### `validate`

Проверяет синтаксическую и структурную корректность файла манифеста `lacie.toml`.

```bash
lacie validate [путь/к/lacie.toml]
```

Проверяет:
- Корректность идентификаторов пакетов и секций TOML.
- Валидность и уникальность названий целевых платформ (таргетов).
- Наличие обязательных полей (`name`, `version`, бинарники).
- Хэши SHA256 файлов, если они присутствуют на локальном диске.

---

### `gen-toml`

Создает стартовый шаблон файла `lacie.toml` в текущем рабочем каталоге.

```bash
lacie gen-toml
```

---

### `completions`

Генерирует скрипты автодополнения для командной строки.

```bash
lacie completions <оболочка>
```

Поддерживаемые оболочки: `bash`, `zsh`, `fish`, `powershell`.

Пример:
```bash
# Для Fish
lacie completions fish > ~/.config/fish/completions/lacie.fish

# Для Bash
lacie completions bash >> ~/.bash_completion
```

---

### `explain`

Выводит подробное описание и инструкции по устранению кодов ошибок и предупреждений.

```bash
lacie explain <КОД>
```

Пример:
```bash
lacie explain E001
lacie explain W003
```

---

### `suicide`

Полностью деинсталлирует Lacie и удаляет все связанные файлы.

```bash
lacie suicide [опции]
```

**Опции:**
- `-y`, `--yes`: выполнить удаление без запроса подтверждения.

Команда выполняет:
1. Удаление всех скачанных бинарников, симлинков и баз данных.
2. Удаление каталога `active/` из профилей оболочек (`.bashrc`, `.zshrc` и т.д.).
3. Удаление домашней директории Lacie.

---

### Версия и справка

- `lacie`: выводит название, лицензию и ссылку на репозиторий проекта.
- `lacie -v`, `lacie --version`: выводит версию и подсказку по вызову справки.
- `lacie --help`: выводит стандартную справку по доступным командам.

## 5. Синтаксис фильтров

Команды управления (например, `lacie list`) поддерживают структурированные фильтры:

### Синтаксис
- `ключ:значение`: точное совпадение поля.
- `not-ключ:значение`: отрицание (поле не равно значению).
- `ключ:знач1,знач2`: совпадение с любым из перечисленных значений (логическое ИЛИ).
- `ключ:мин..макс`: диапазон чисел или версий (включительно).
- `ключ:мин..`: значение больше или равно `мин`.
- `ключ:..макс`: значение меньше или равно `макс`.

### Доступные ключи
- `name`: имя пакета.
- `command`: имя исполняемого файла в PATH.
- `id`: уникальный идентификатор домена (например, `com.example.tool`).
- `author`: автор пакета.
- `link`: ссылки или URL репозитория.
- `source`: источник пакета (например, `github`).
- `storage`: путь в источнике (`owner/repo`).
- `version`: строка версии.
- `number`: целочисленный счетчик версий.
- `installed`: дата установки.
- `released`: дата выпуска upstream-релиза.
- `hash`: SHA256-хэш бинарного файла.
- `active`: состояние активности (`true`/`false`).
- `frozen`: статус заморозки (`true`/`false`).
- `unused`: наличие неактивных сохраненных версий.

### Примеры фильтрации
```bash
# Поиск пакетов автора
lacie list author:shareui

# Исключить пакеты из GitHub
lacie list not-source:github

# Только замороженные пакеты
lacie list frozen:true

# Фильтр по диапазону версий
lacie list version:1.0.0..2.0.0
```

## 6. Параметры конфигурации

Настройки хранятся в файле `config.toml` в домашнем каталоге Lacie.

| Ключ | Тип | Допустимые значения | По умолчанию | Описание |
|---|---|---|---|---|
| `language` | string | `auto`, `en`, `ru` | `auto` | Язык сообщений и интерфейса |
| `colors` | string | `terminal`, `always`, `never` | `terminal` | Режим цветового оформления терминала |
| `verify_sha256` | boolean | `true`, `false` | `true` | Обязательная проверка SHA256 файлов |
| `auto_switch` | boolean | `true`, `false` | `true` | Автоматически активировать новые версии |
| `confirm` | boolean | `true`, `false` | `true` | Запрашивать подтверждение перед операциями |
| `always_show` | boolean | `true`, `false` | `false` | Всегда открывать просмотрщик манифеста при установке |
| `cache_ttl` | integer | Минуты ($\ge 0$) | `10` | Время жизни кэша запросов и списков релизов |
| `default_source`| string | Имя источника | `github` | Источник по умолчанию, если не указан явно |
| `windows_priority` | string | `msvc`, `mingw` | `msvc` | Приоритетный ABI для Windows 11 |

## 7. Переменные окружения

| Переменная | Назначение |
|---|---|
| `LACIE_HOME` | Переопределяет путь к домашнему каталогу Lacie, где хранятся файлы и бинарники. |
| `LACIE_GH_TOKEN` | Персональный токен доступа GitHub (`ghp_...`). Позволяет обойти лимит анонимных запросов (60 запросов/час) и устанавливать пакеты из приватных репозиториев. |
| `NO_COLOR` | Если переменная задана, вывод терминала полностью лишается управляющих ANSI-последовательностей цветов. |
