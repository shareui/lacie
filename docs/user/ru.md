## 1. Обзор и концепция

Lacie устанавливает готовые исполняемые файлы без необходимости прав суперпользователя (`root` / администратор).

Ключевые принципы:
- **Модель нулевого доверия:** релизы обязаны предоставлять контрольные суммы. Непроверенные манифесты и скрипты жизненного цикла требуют подтверждения перед запуском.
- **Сосуществование версий:** разные версии одного пакета хранятся параллельно в каталоге `bin/{id}/{version}/`. В `PATH` активна только одна версия, но переключение между ними происходит мгновенно.
- **Безопасные обновления:** при обновлении новая версия скачивается рядом со старой. Если обновление работает нестабильно, можно сразу вернуть предыдущую версию.
- **Управление ссылками:** в Unix-системах Lacie создает символические ссылки в `active/`. В Windows 11 активный бинарник копируется в `active/`.
- **Оптимизация локальных установок:** при установке из локальных архивов или файлов без интернета Lacie не использует искусственные сетевые шкалы прогресса, а сразу выполняет мгновенную распаковку и копирование.

## 2. Установка и первый запуск

### Начальная настройка (`init-lacie`)

Инициализируйте рабочее окружение командой:

```bash
lacie init-lacie
```

Интерактивный мастер задаст 5 основных вопросов:
1. **Language:** язык интерфейса — русский (`ru`), английский (`en`) или автоопределение (`auto`).
2. **Colors:** цветовая схема терминала (`terminal`), 256 цветов (`always`) или отключено (`never`).
3. **Verify SHA256:** строгая проверка контрольных сумм скачиваемых файлов (`true`/`false`).
4. **Auto Switch:** автоматическая активация только что установленной версии (`true`/`false`).
5. **Confirm:** запрос подтверждения перед установкой, обновлением или удалением (`true`/`false`).

### Настройка переменной PATH

Lacie размещает исполняемые файлы в каталоге `active/`:
- **Unix:** `~/lacie/active`
- **Windows:** `%LOCALAPPDATA%\lacie\active`

Добавьте этот путь в переменную окружения `PATH`:

#### Bash / Zsh (`~/.bashrc` или `~/.zshrc`):
```bash
export PATH="$HOME/lacie/active:$PATH"
```

#### Fish (`~/.config/fish/config.fish`):
```fish
fish_add_path ~/lacie/active
```

#### Windows (PowerShell):
```powershell
[Environment]::SetEnvironmentVariable("Path", $env:Path + ";$env:LOCALAPPDATA\lacie\active", "User")
```

## 3. Форматы ссылок на пакеты

Lacie распознает следующие форматы целевых пакетов:

| Формат | Назначение | Пример |
|---|---|---|
| `owner/repo` | Репозиторий через `default_source` (по умолчанию: `github`) | `lacie add shareui/nyano` |
| `source:owner/repo` | Явное указание плагина источника | `lacie add github:shareui/nyano` |
| `source:owner/repo#pkg` | Конкретный пакет из мультипакетного репозитория | `lacie add github:shareui/lacie#tool` |
| `source:owner/repo 1.2.0` | Конкретная версия или тег релиза | `lacie add github:shareui/nyano 1.0.0` |
| `https://.../archive.tar.gz` | Прямая ссылка на архив через HTTP/HTTPS | `lacie add https://example.com/bin.tar.gz` |
| `/path/to/archive.tar.gz` | Локальный файл архива (`.tar.gz`, `.tar.xz`, `.tar.zst`, `.zip`) | `lacie add ./pkg-v1.tar.gz` |
| `/path/to/lacie.toml` | Локальный файл манифеста | `lacie add ./lacie.toml` |

## 4. Справочник команд

### Command: init-lacie

Инициализирует или перенастраивает рабочее окружение Lacie, интеграцию с командной оболочкой и параметры конфигурации.

```bash
lacie init-lacie [QUESTION_ID] [опции]
```

**Параметры:**
- `[QUESTION_ID]`: Необязательный идентификатор для перехода к конкретному шагу настройки:
  - `1` или `lang`: выбор языка интерфейса (`auto`, `en`, `ru`).
  - `2` или `color`: выбор режима цветового оформления (`terminal`, `always`, `never`).
  - `3` или `verify`: обязательная проверка SHA256 (`true`/`false`).
  - `4` или `path`: добавление каталога `active/` в системный `PATH`.
  - `5` или `switch`: автоматическое переключение на новую версию при установке (`true`/`false`).

**Опции и флаги:**
- `--recfg`: повторно задать вопросы, даже если они уже были настроены ранее.

**Примеры:**
```bash
# Полная пошаговая интерактивная настройка
lacie init-lacie

# Перенастроить только цветовую схему
lacie init-lacie color --recfg

# Перенастроить добавление в PATH
lacie init-lacie path --recfg
```

### Command: add

Устанавливает пакеты из внешних источников, по прямым ссылкам или из локальных файлов.

```bash
lacie add <ссылка-на-пакет> [версия] [опции]
```

**Параметры:**
- `<ссылка-на-пакет>`: Идентификатор целевого пакета: короткая ссылка `owner/repo`, `source:owner/repo`, прямая HTTP/HTTPS-ссылка на архив, путь к локальному архиву (`.tar.gz`, `.tar.xz`, `.tar.zst`, `.zip`) или путь к файлу манифеста (`.toml`).
- `[версия]`: Необязательный тег релиза или номер версии (по умолчанию: `latest`).

**Опции и флаги:**
- `-y`, `--yes`: пропустить запрос подтверждения и выполнить установку автоматически.
- `--show`: открыть полноэкранный интерактивный терминальный просмотрщик манифеста и скриптов перед подтверждением.
- `--list`: вывести список доступных upstream-релизов и тегов репозитория без скачивания.
- `--info`: вывести метаданные пакета и поддерживаемые архитектуры без установки.
- `--force`: принудительно переустановить пакет, даже если такая версия уже присутствует.
- `--set-hash <sha256>`: явно задать ожидаемый SHA256-хэш, если в манифесте он отсутствует.
- `--ignore-hash`: пропустить проверку контрольной суммы SHA256 (вызывает предупреждение `W002`, не рекомендуется).
- `--max <n>`: ограничить количество выводимых вариантов при неоднозначном поиске.
- `-b`, `--no-bar`: скрыть прогресс-бар в скобках, сохранив числовую статистику.

**Локальная и сетевая установка:**
- При установке локальных файлов без доступа к сети Lacie переходит в локальный режим: отображаются действия `Unpacking` или `Copying` без искусственных задержек и фейковых скоростей загрузки.
- При скачивании из сети отображается стрелочный прогресс-бар `[-----> ... ]`, скорость и объем переданных данных.

**Управление в интерактивном просмотрщике (`--show`):**
- `n`: следующий файл в очереди просмотра.
- `p`: предыдущий файл в очереди просмотра.
- `a`: одобрить пакет и продолжить установку.
- `d` / `q`: отклонить пакет и отменить операцию.

**Примеры:**
```bash
# Установка пакета из источника по умолчанию (GitHub)
lacie add shareui/nyano

# Установка определенной версии
lacie add shareui/nyano 0.2.0

# Установка из локального архива без интернета
lacie add ./yukino-lsp-0.1.0.tar.gz

# Проверка содержимого манифеста и скриптов перед подтверждением
lacie add shareui/nyano --show

# Принудительная установка с явным хэшем
lacie add shareui/nyano --force --set-hash e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```

### Command: update

Проверяет наличие свежих релизов и обновляет установленные программы.

```bash
lacie update [пакеты...] [опции]
```

Если список пакетов не указан, Lacie проверяет все установленные пакеты (кроме замороженных и установленных из локальных файлов).

**Параметры:**
- `[пакеты...]`: Необязательный список имен или идентификаторов пакетов для проверки и обновления.

**Опции и флаги:**
- `-a`, `--all`: явно проверить и обновить все установленные пакеты.
- `-y`, `--yes`: применить все найденные обновления без интерактивного подтверждения.
- `-d`, `--dry-run`: проверить доступность обновлений и вывести список без скачивания и внесения изменений.
- `-i`, `--ignore <пакет>`: исключить указанный пакет из проверки (можно указывать несколько раз).
- `--pre`: учитывать предварительные выпуски (alpha, beta, rc).
- `--no-cache`: игнорировать локальный кэш релизов и запросить свежие данные из реестра.
- `-b`, `--no-bar`: скрыть визуальную шкалу прогресс-бара.

**Поведение:**
- Обновления скачиваются параллельно со старыми версиями. Если включен параметр `auto_switch`, активная ссылка сразу переключается на новый бинарник. Предыдущие версии остаются в `bin/` и могут быть активированы в любой момент командой `lacie switch`.

**Примеры:**
```bash
# Интерактивная проверка и обновление всех пакетов
lacie update

# Автоматическое обновление всех пакетов без подтверждения
lacie update -y

# Проверка обновлений без скачивания файлов
lacie update --dry-run

# Обновление пакета с учетом пре-релизов
lacie update ripgrep --pre

# Обновить все пакеты кроме neovim
lacie update --all --ignore neovim
```

### Command: switch

Мгновенно переключает активную версию установленного пакета без повторного скачивания.

```bash
lacie switch <пакет> <версия> [<пакет2> <версия2> ...]
```

**Параметры:**
- `<пакет>`: Имя или ID установленного пакета.
- `<версия>`: Номер установленной версии для активации в `active/` (PATH).
- В одной команде можно передать несколько пар пакетов и версий.

**Примеры:**
```bash
# Переключить ripgrep на версию 13.0.0
lacie switch ripgrep 13.0.0

# Переключить сразу несколько программ
lacie switch ripgrep 13.0.0 neovim 0.9.5
```

### Command: remove

Удаляет пакеты или очищает неактивные версии с диска.

```bash
lacie remove <пакеты...> [опции]
```

**Параметры:**
- `<пакеты...>`: Одно или несколько имен либо ID пакетов для удаления.

**Опции и флаги:**
- `-y`, `--yes`: не запрашивать подтверждение и удалить пакеты сразу.
- `--unused`: удалить только старые/неактивные версии, сохранив текущую активную.
- `--symlink-only`: удалить ссылку/бинарник из `active/`, не удаляя файлы из `bin/`.
- `--active-only`: удалить только текущую активную версию.
- `--no-scripts`: не выполнять скрипты удаления (`preremove.rb` и `postremove.rb`).

**Безопасность:**
- Перед запуском скриптов удаления Lacie проверяет их хэш по базе `scripts.toml`. Если скрипт был модифицирован вручную, запуск блокируется с ошибкой `E035`.

**Примеры:**
```bash
# Полное удаление пакета
lacie remove ripgrep

# Удаление старых кэшированных версий
lacie remove ripgrep --unused

# Отключение команды из PATH без удаления файлов
lacie remove ripgrep --symlink-only
```

### Command: freeze

Замораживает пакет на текущей активной версии, защищая его от обновлений.

```bash
lacie freeze <пакет|ALL>
```

**Параметры:**
- `<пакет>`: Имя или ID пакета для заморозки.
- `ALL`: Заморозить все установленные пакеты на их активных версиях.

**Поведение:**
- Замороженные пакеты помечаются `[frozen]` в `lacie list` и полностью игнорируются при запуске `lacie update`.

**Примеры:**
```bash
# Заморозить отдельный пакет
lacie freeze neovim

# Заморозить все установленные программы
lacie freeze ALL
```

### Command: unfreeze

**Параметры:**

**Примеры:**
```bash
# Разморозить пакет
```

### Command: rename

Изменяет имя исполняемого файла или ссылки в каталоге `active/` (PATH).

```bash
lacie rename <пакет> <новое-имя|DEFAULT>
```

**Параметры:**
- `<пакет>`: Имя или ID целевого пакета.
- `<новое-имя>`: Желаемое имя команды в терминале.
- `DEFAULT`: Возвращает исходное имя команды, заданное в манифесте пакета.

**Примеры:**
```bash
# Сделать команду neovim доступной как nvim
lacie rename neovim nvim

# Сбросить имя команды на значение по умолчанию
lacie rename neovim DEFAULT
```

### Command: source

Управляет источниками пакетов и плагинами реестров.

```bash
lacie source <подкоманда> [опции]
```

**Подкоманды:**
- `lacie source list`: выводит список всех зарегистрированных источников с версией, происхождением, автором и статусом (`builtin`, `active`, `disabled`).
- `lacie source add <имя> <ссылка> [опции]`: регистрирует новый источник из Git-репозитория или локального каталога.
  - `-y`, `--yes`: не запрашивать подтверждение.
- `lacie source remove <имя> [опции]`: удаляет сторонний плагин источника. Встроенные плагины (например, `github`) удалить нельзя.
  - `-y`, `--yes`: не запрашивать подтверждение.
- `lacie source update [имя] [опции]`: обновляет плагины источников из их репозиториев.
  - `-y`, `--yes`: не запрашивать подтверждение.
- `lacie source enable <имя>`: включает ранее отключенный источник.
- `lacie source disable <имя>`: отключает источник без удаления его файлов.

**Примеры:**
```bash
# Список всех источников
lacie source list

# Добавление стороннего реестра
lacie source add community shareui/lacie-community-plugin

# Временное отключение источника
lacie source disable community
```

### Command: info

Отображает подробные метаданные, историю версий, размеры файлов и контрольные суммы пакетов.

```bash
lacie info <пакеты...>
```

**Параметры:**

**Состав вывода:**

**Примеры:**
```bash
# Информация об одном пакете
lacie info ripgrep

# Информация о нескольких пакетах в рамках
lacie info ripgrep neovim fd
```

### Command: doctor

Проверяет состояние рабочего окружения, права доступа, целостность ссылок и баз данных.

```bash
lacie doctor [опции]
```

**Опции и флаги:**
- `--fix`: автоматически устранить обнаруженные проблемы (создать отсутствующие папки, выставить права `0700`/`0755`, восстановить поврежденные симлинки и базы данных).

**Область проверки:**
- Структура домашнего каталога Lacie и права доступа.
- Конфигурация оболочек и наличие каталога `active/` в `PATH`.
- Корректность ссылок и права на запуск бинарных файлов.
- Целостность баз `packages.toml`, `sources.toml`, `seen.toml` и `scripts.toml`.
- Работоспособность плагинов источников и среды Ruby.

**Примеры:**
```bash
# Диагностика окружения
lacie doctor

# Автоматическое исправление проблем
lacie doctor --fix
```

### Command: config

Просматривает и изменяет параметры конфигурации в файле `config.toml`.

```bash
lacie config <подкоманда> [опции]
```

**Подкоманды:**
- `lacie config list`: отображает сгруппированный список параметров (`UI & Environment`, `Behavior & Safety`, `Engine & Storage`) со значениями, настройками по умолчанию, маркерами отличий (`*`) и подсказками.
  - Автоматически адаптируется под операционную систему: `windows_priority` видна только на Windows, `linux_priority` — только на Linux, а на macOS/BSD обе строки скрыты.
- `lacie config get <ключ>`: выводит текущее значение указанной настройки.
- `lacie config set <ключ> <значение|DEFAULT>`: задает новое значение параметра. Передача `DEFAULT` сбрасывает параметр на исходное значение по умолчанию.
- `lacie config reset [опции]`: сбрасывает все параметры конфигурации к заводским значениям.
  - `-y`, `--yes`: не запрашивать подтверждение.

**Примеры:**
```bash
# Список параметров конфигурации
lacie config list

# Просмотр текущего языка
lacie config get language

# Изменение источника по умолчанию
lacie config set default_source community

# Сброс запроса подтверждения на значение по умолчанию
lacie config set confirm DEFAULT
```

### Command: export

Экспортирует состояние установленных пакетов в декларативный файл блокировки.

```bash
lacie export [файл] [опции]
```

**Параметры:**
- `[файл]`: Путь к результирующему файлу (по умолчанию: `lacie-lock.toml`) или `-` для вывода в стандартный поток вывода stdout.

**Опции и флаги:**
- `--all-versions`: включить в экспорт все скачанные версии, а не только активные.
- `--with-config`: включить пользовательские настройки конфигурации в файл экспорта.

**Примеры:**
```bash
# Экспорт активных пакетов в lacie-lock.toml
lacie export

# Вывод в stdout для конвейера
lacie export - > my-backup.toml

# Полный экспорт всех версий и конфигурации
lacie export backup.toml --all-versions --with-config
```

### Command: import

Восстанавливает состояние пакетов из экспортированного файла блокировки.

```bash
lacie import [файл]
```

**Параметры:**
- `[файл]`: Путь к файлу блокировки (по умолчанию: `lacie-lock.toml`) или `-` для чтения из stdin.

**Примеры:**
```bash
# Восстановление из стандартного файла
lacie import

# Восстановление из указанного файла
lacie import backup.toml

# Восстановление из потока stdin
cat backup.toml | lacie import -
```

### Command: validate

Проверяет синтаксис, обязательные поля и структуру манифеста `lacie.toml`.

```bash
lacie validate [путь/к/lacie.toml]
```

**Параметры:**
- `[путь]`: Путь к проверяемому манифесту (по умолчанию: `./lacie.toml`).

**Проверяемые критерии:**
- Формат обратного доменного имени пакетов (`com.example.app`).
- Валидность целевых триплетов архитектур.
- Наличие обязательных полей (`name`, `version`, записи бинарников).
- Соответствие контрольных сумм локальных файлов на диске.

**Примеры:**
```bash
# Проверка манифеста в текущей папке
lacie validate

# Проверка по указанному пути
lacie validate path/to/lacie.toml
```

### Command: explain

Выводит расширенное объяснение и пошаговые инструкции по устранению ошибок и предупреждений.

```bash
lacie explain <КОД>
```

**Параметры:**
- `<КОД>`: Код ошибки (например, `E001`–`E036`) или предупреждения (например, `W001`–`W007`).

**Примеры:**
```bash

lacie explain E006

# Пояснение несовпадения хэша
lacie explain E007

# Пояснение предупреждения о запасной сборке
lacie explain W003
```

### Command: suicide

Полностью и безвозвратно удаляет Lacie и все связанные файлы из системы.

```bash
lacie suicide [опции]
```

**Опции и флаги:**
- `-y`, `--yes`: пропустить подтверждение и выполнить удаление немедленно.

**Выполняемые действия:**
1. Деактивирует и удаляет все ссылки и исполняемые файлы из `active/` и `bin/`.
2. Удаляет базы данных, кэш и плагины.
3. Очищает строки настройки `PATH` в конфигурационных файлах оболочек (`.bashrc`, `.zshrc`, `config.fish`).
4. Удаляет корневой каталог Lacie.

**Примеры:**
```bash
# Удаление с подтверждением
lacie suicide

# Немедленное удаление без вопросов
lacie suicide -y
```

## 5. Синтаксис фильтров

Команды вроде `lacie list` поддерживают гибкие выражения для фильтрации пакетов:

### Синтаксис
- `ключ:значение`: точное совпадение поля со значением.
- `not-ключ:значение`: отрицание (поле не должно равняться значению).
- `ключ:знач1,знач2`: совпадение с любым из перечисленных значений (логическое ИЛИ).
- `ключ:мин..макс`: диапазон чисел или версий (включительно).
- `ключ:мин..`: значение больше или равно `мин`.
- `ключ:..макс`: значение меньше или равно `макс`.

### Доступные ключи
- `name`: имя пакета.
- `command`: имя исполняемого файла в PATH.
- `id`: уникальный идентификатор домена (например, `com.example.tool`).
- `author`: автор пакета.
- `link`: ссылки или URL репозитория.
- `source`: источник пакета (например, `github`).
- `storage`: путь в источнике (`owner/repo`).
- `version`: строка версии.
- `number`: целочисленный счетчик версий.
- `installed`: дата установки.
- `released`: дата выпуска upstream-релиза.
- `hash`: SHA256-хэш бинарного файла.
- `active`: состояние активности (`true`/`false`).
- `frozen`: статус заморозки (`true`/`false`).
- `unused`: наличие неактивных сохраненных версий.

### Примеры фильтрации
```bash
# Поиск пакетов автора
lacie list author:shareui

# Исключить пакеты из GitHub
lacie list not-source:github

# Только замороженные пакеты
lacie list frozen:true

# Фильтр по диапазону версий
lacie list version:1.0.0..2.0.0
```

## 6. Параметры конфигурации

Настройки хранятся в файле `config.toml` в домашнем каталоге Lacie.

| Ключ | Тип | Допустимые значения | По умолчанию | Описание |
|---|---|---|---|---|
| `language` | string | `auto`, `en`, `ru` | `auto` | Язык сообщений и интерфейса |
| `colors` | string | `terminal`, `always`, `never` | `terminal` | Режим цветового оформления терминала |
| `verify_sha256` | boolean | `true`, `false` | `true` | Обязательная проверка SHA256 файлов |
| `auto_switch` | boolean | `true`, `false` | `true` | Автоматически активировать новые версии |
| `confirm` | boolean | `true`, `false` | `true` | Запрашивать подтверждение перед операциями |
| `always_show` | boolean | `true`, `false` | `false` | Всегда открывать просмотрщик манифеста при установке |
| `cache_ttl` | integer | Минуты ($\ge 0$) | `10` | Время жизни кэша запросов и списков релизов |
| `default_source`| string | Имя источника | `github` | Источник по умолчанию, если не указан явно |
| `windows_priority` | string | `msvc`, `mingw` | `msvc` | Приоритетный ABI для Windows 11 (только Windows) |
| `linux_priority` | string | `glibc`, `musl` | автоопределение в runtime (`glibc`/`musl`) | Приоритетный ABI libc для Linux (только Linux) |

## 7. Переменные окружения

| Переменная | Назначение |
|---|---|
| `LACIE_HOME` | Переопределяет путь к домашнему каталогу Lacie, где хранятся файлы и бинарники. |
| `LACIE_GH_TOKEN` | Персональный токен доступа GitHub (`ghp_...`). Позволяет обойти лимит анонимных запросов (60 запросов/час) и устанавливать пакеты из приватных репозиториев. |
| `NO_COLOR` | Если переменная задана, вывод терминала полностью лишается управляющих ANSI-последовательностей цветов. |
